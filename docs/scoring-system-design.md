## 0. 结论先行

旧的评估代码（Station 4 + MAAS-Global 双轨，取平均）**已随数据换代失效**，但即使修好它也不该用——
它是我们自己造的，与医院给的 `R01–R14` 不是一回事。三个转向：

| 维度 | 现在（旧代码） | 目标 |
|---|---|---|
| **评分标准** | 自造双轨（Station 4 五维 + MAAS 六维） | **医院的 `R01–R14`**，外加我们的结构性改良 |
| **谁来判** | LLM 直接给总分 | **LLM 只判锚点是否命中并引用原话，代码算分** |
| **安全错误** | `(诊断 + 沟通) / 2` 平均掉 | **独立通道，不参与任何平均** |
| **不可评价** | 无此概念，失败=0 分 | **NE / NA / SKIPPED_SAFETY 由代码判定，同时报告可评上限** |

一句话：**把「让模型打个分」换成「让模型回答一串可证伪的小问题，代码把它们变成分数」。**

## 1. 两条评估线 = R14 的内在结构

需求方的表述是两条线：**① 最终报告是否准确；② 对话过程是否合规、是否有素养。**
这两条线不需要我们另外发明——**医院数据的分组就是它**，只是没有明确说出来。
依据是 `R01–R14` 每项背后的「参照 ID」栏（证据从哪来）：

| 项 | 证据来源 | 参照 ID |
|---|---|---|
| R01 主诉与病程询问 | 🗣 对话 | H01 H02 |
| R02 鉴别症状及危险征象询问 | 🗣 对话 | H03 H04 |
| R03 诊疗史、用药和全身风险 | 🗣 对话 | H05 H06 H07 |
| R04 必要检查选择 | 🗣 对话中**实际申请了哪些检查** | E01–E03 |
| R05 检查结果解释与边界 | 🗣 对话 | E01–E04 |
| R06 诊断与部位/确定性 | 📝 **最终作答** | D01 |
| R07 诊断理由 | 📝 **最终作答** | D02 + E |
| R08 鉴别诊断分析 | 📝 **最终作答** | DD01 DD02 |
| R09 近期处理和安全优先 | 📝 **最终作答** | T01 |
| R10 阶段计划与复评 | 📝 **最终作答** | T02 T03 |
| R11 病情及计划解释 | 🗣 对话（原文：「须在患者对话中体现」） | G01 |
| R12 注意事项与安全告知 | 🗣 对话 | G02 |
| R13 担忧、偏好与理解核查 | 🗣 对话 | P01 P02 P03 |
| R14 尊重表达与术语使用 | 🗣 对话 | P03 |

**9 项看对话，5 项看最终作答。** 于是报告天然分两个视图（§9），而**不是两个各 100 分再平均**。

### 医院写死的三条规则（决定了实现方式）

原文（`_docx.txt:100`）：
> 「**临床方案正确与向患者解释是不同证据。诊断猜中但理由缺失，R06 可以得分而 R07 不能由系统补分；
> 诊疗框写了计划，不代表 R11 已经完成。**」

→ 两条证据链**必须独立计分，不许互相补分**。

原文（`_docx.txt:193`）：
> 「**评分证据须引用学员原话、检查申请或作答片段。**」

→ 每一个分都要能指回具体证据。这决定了我们的输出结构（§6）。

原文（`_docx.txt:100` 后半）：
> 「**检查选择计分看学员实际请求及其合理性，不能因系统宽召回了整个 E 包，就把包内全部项目记为学员已主动选择。**」

→ 这是我们检查模块「宽召回」的**直接警告**。见 §7.2。

## 3. 第一步：把评分素材挖出来

### 3.1 为什么是确定性解析，不是 LLM

格式是**逐行、编号固定、每例同构**的——这和 `extract_behavior_tests.py` 处理 B 模块是同一类问题。
**用正则解析，不用 LLM。** 理由：
- 可复现、可回归、零成本；
- 数据是**医疗标准答案**，任何 LLM 改写都是污染（P1 风险）；
- 解析失败是**可定位的错误**，LLM 幻觉失败是**不可定位的错误**。

### 3.2 新增脚本

| 脚本 | 作用 | 输入 → 输出 |
|---|---|---|
| `scripts/extract_answer_key.py` | 解析 A2 隐藏块 | `_docx.txt` → `data/staging/<case>.answer.new.json` |
| `scripts/extract_rubric.py` | 解析 A3 页 + 册前全局 | `_docx.txt` → `data/staging/<case>.rubric.new.json` + `data/scoring/rubric_common.json` |
| `scripts/verify_scoring_data.py` | 校验 A1–A7（见下），**通过才提升** | staging → `data/cases/` |

> 沿用既有目录约定：`data/staging/` 中间产物，`data/cases/` 只放最终进系统的数据。

### 3.3 校验规则（继承 `build_exam_v2.py` 的思路：**提取后必须证明**）

| # | 规则 | 为什么 |
|---|---|---|
| **A1** | 每例必须恰好有 D01 / D02 / ≥1 个 DD / T01 / G01 / G02 | 缺一项 = 某条 R 无从判定 |
| **A2** | 每例必须恰好 14 条 R 行，ID 为 R01–R14 且不重不漏 | 框架完整性 |
| **A3** | 每条 R 的「参照 ID」必须在 H/P/E/D/DD/T/G 中有定义 | 证据链闭合 |
| **A4** | R06 的参照必须是 D01；R07 含 D02；R08 含 DD\*；R09 含 T01；R10 含 T02/T03；R11 含 G01；R12 含 G02；R13 含 P01/P02 | 逐条对齐医院设计 |
| **A5** | 每例必须恰好 1 行 `关键错误`（可为空串） | 安全通道 |
| **A6** | 解析不出标签的行（如 DD 的名称/理由切不开）**报错，不静默丢弃** | 同上 |
| **A7** | **逐字保真**：每条锚点/参考答案文本必须是 docx 原文的连续子串 | 医学内容只能誊抄（P1）——防流水线悄悄改写 |

**验收目标**：30 例全部通过 A1–A7，或产出**一份明确的例外清单**（如 SU06 缺 A2）。
**已达成（2026-10-12）**：29/30 通过（SU06 缺隐藏块），**逐字保真 120/120**，5 例已提升。
A7 已做**负向测试**：改一个字即报错、阻断提升。

## 4. 参考答案的形态与用法

### 4.1 形态：不是「一段标准文本」，是「一张判定清单」

**不要**把参考答案存成一大段话让 LLM 去"感觉像不像"。要存成**结构化的、可逐条证伪的清单**：

```jsonc
// data/cases/en01.answer.json（示例）
{
  "case_id": "EN01",
  "diagnosis": {
    "primary": "36深龋，36可复性牙髓炎",
    "reasoning": "短暂刺激痛且无自发、夜间痛，冷测可恢复，叩诊阴性，配合深龋影；不能仅由影像厚度保证牙髓组织学正常。"
  },
  "differentials": [
    {"id": "DD01", "label": "症状性不可复性牙髓炎",
     "excluded_because": "本例缺少持续冷痛、自发和夜间痛；仍需治疗中及随访复评牙髓状态。"},
    {"id": "DD02", "label": "牙本质敏感",
     "excluded_because": "也可为短暂刺激痛，但本例存在深龋洞，不应只用脱敏解释。"}
  ],
  "plan": {
    "immediate": {"id": "T01", "content": "评估可修复性及牙髓状态，解释保髓目标；…"},
    "definitive": {"id": "T02", "content": "在适用病例中考虑选择性去龋和可靠修复；…"},
    "review":     {"id": "T03", "content": "个体化防龋、减少游离糖摄入频次，安排修复与牙髓复查；…"}
  },
  "communication_reference": {
    "explain": {"id": "G01", "content": "目前表现更支持牙髓能恢复；…"},
    "warn":    {"id": "G02", "content": "避免反复冷热刺激；出现自发痛、持续痛或肿胀及时复诊；…"}
  },
  "evidence_basis": ["K01", "K02", "K03"],
  "answer_sheet": {          // 反推的答卷五项 → 参考答案 ID（机器可读，不靠记忆）
    "diagnosis": "D01", "reason": "D02", "differential": "DD*",
    "immediate_plan": "T01", "staged_plan": "T02+T03"
  }
}
```

> **实现偏差（2026-10-12）**：`critical_errors` 实际落在 `*.rubric.json`，不在本文件——
> 它在 A3「病例评分依据」页上，与 R 锚点同页。以 `scripts/extract_answer_key.py` 的真实输出为准。

**为什么这样存**：
- R06/R07/R08/R09/R10 各自能**精确对上**一个字段，不用 LLM 在一大段里找；
- `differentials` 是**列表**——R08 的判分天然是「学生列出了几个关键鉴别 + 说没说区分依据」；
- `critical_errors` 是**数组**——安全通道逐条独立判（§8）。

### 4.2 用法：只进评分链路，永不下发

| 读者 | 能读到 |
|---|---|
| 评分链路（evaluator 将来时） | ✅ `answer_key` + `rubric` |
| 患者 Agent | ❌ **绝不** |
| 检查模块 | ❌ **绝不** |
| 学员端 API | ❌ **绝不**（提交后也不直接回显原文） |

**存储方案**：新增一列 `Case.answer_key`（JSON），与 `Case.data` / `Case.exam_data` **并列但互不可见**。
患者流水线只读 `Case.data`，这条边界**不是靠提示词，是靠不传**（沿用既有哲学）。

> ⚠️ **这是本次改动唯一的高危点**：病例标题里本来就有诊断，我们当初特意把标题剔掉了；
> 现在参考答案又把诊断放回来。**必须证明它进不了患者侧。** 见 §11 的「隔离回归测试」。

### 4.3 学员答卷：五项（2026-10-12 定）

医院文档里出现过「**学员四项作答**」这五个字，但**从未列举是哪四项**。等医院答复前，先按反推的五项做
（依据 R06–R10 加教师参考的对应字段）：

| 答卷项 | 对应 R | 参考答案 ID |
|---|---|---|
| ① 诊断（部位 + 确定性） | R06 | D01 |
| ② 诊断理由 | R07 | D02 |
| ③ 鉴别诊断（+ 区分依据） | R08 | DD\* |
| ④ 近期处理 | R09 | T01 |
| ⑤ 阶段计划与复评 | R10 | T02 + T03 |

**现有表单要改的地方**：`primary_diagnosis` 要能表达**确定性**（R06 原文是「诊断与部位/确定性」）；
`differential_diagnosis` 要能装**区分依据**（R08 要「说明区分依据」）；`treatment_plan` 要拆成
**近期处理 / 阶段计划**两项；**`suggested_exams` 应删**——R04 看的是对话里实际申请过什么，
留一个事后填空的字段反而制造漏洞（学生可以补写压根没问过的检查）。

> 这份对应关系已用机器可读的方式写进 `*.answer.json` 的 `answer_sheet` 字段，靠数据而不是靠记忆。

## 5. 评分框架（改良版）

医院给的是 **14 项 × 0/1/2 分，上限 28 分**，并明确说：
> 「项目数和分值均为本次开发草案，尚未验证；没有官方及格线。」（`_docx.txt:98`）
> 医生批注（`data/raw/_comments.txt`）：「**评分非均匀分配，权重后续需专家讨论决定**」

需求方已明确：**硬性医学知识必须贴文档，但系统设计允许改良优化。** 因此下面六条改良**不动医学内容**，
只动「怎么把锚点变成分」。

### 5.1 改良一：把每一项拆成「子锚点」

医院的 2 分锚点是**多分句合取**——比如 R01：
> 正确询问本例部位、时间及发展经过：`<H01 内容>`；`<H02 内容>`。

它其实是「部位/时间」+「发展经过」两个子要求。拆开：

```jsonc
{"id": "R01", "sub_anchors": [
   {"n": 1, "criterion": "询及主诉部位与时间", "refs": ["H01"], "evidence": "dialogue"},
   {"n": 2, "criterion": "询及发展经过",       "refs": ["H02"], "evidence": "dialogue"}
]}
```

**收益**：
- **部分给分有据**——对应 1 分锚点「部分达到」；
- **每个子锚点挂 ref id**——可追溯到 H/P/E/D/T/G，满足医院的「证据编号」要求；
- **可静态检查覆盖率**——不会有整条 R 从未被任何测试触发。

### 5.2 改良二：判定分工——能交给代码的绝不交给模型

这是**本设计最重要的一条**，也是为什么我们现在做评分比旧代码有质的优势——
**前面的患者/检查模块已经替我们记下了证据。**

| 项 | 判定方式 | 依据 | 说明 |
|---|---|---|---|
| R01 | 🟢 **代码** | `Message.disclosed` 含 H01+H02 | 披露轨迹 = 学员问到了 |
| R02 | 🟢 **代码** | `disclosed` 含 H03+H04 | 同上 |
| R03 | 🟢 **代码** | `disclosed` 含 H05/H06/H07 | 同上 |
| R04 | 🟢 **代码** | 申请轨迹 ⊇ 该例 `level=="关键"` 的 E 项 | 见 §7.2 |
| R05 | 🔵 LLM | 对话 + E 结果 | 语义判断（解释是否准确、是否把缺失当阴性） |
| R06–R10 | 🔵 LLM | 作答 + `answer_key` | 语义比对判定清单 |
| R11–R14 | 🔵 LLM | 对话 + `answer_key.communication_reference` | 沟通/人文 |

**4 项纯代码（R01–R04），10 项 LLM。** 而且 LLM 那 10 项也被 `answer_key` 约束成「对照清单逐条回答」。

> 旧代码的问题是：14 件事全丢给 LLM 一次算完，既不可复现又不可追溯。
> 新分工下，**最容易出错、最不该由模型裁决的四项（问没问到、查没查）完全脱离模型。**

### 5.3 改良三：证据强制（对应医院「须引用学员原话」）

LLM 对每个子锚点必须输出：

```jsonc
{"item": "R07", "sub_anchor": 1, "met": true,
 "evidence_quote": "因为冷测之后疼痛很快就缓解了，而且没有夜间痛",
 "evidence_ref": "msg#23"}
```

**规则：`met: true` 而没有 `evidence_quote` 的判定，一律降级为「未命中」。**
这样模型**无法凭空给分**——它想给分就得先把原话抄出来。这是把 P1（忠诚优先于聪明）搬到评分侧。

### 5.4 改良四：聚合规则显式化

子锚点 → 项分：

| 命中比例 | 项分 |
|---|---|
| 全部命中 | 2 |
| 部分命中（≥1 但未全） | 1 |
| 全部未命中 **或命中但错误** | 0 |

对应医院册前的 1 分锚点「部分完成」、0 分锚点「未完成或错误」。**聚合由代码做，不由模型做。**

## 6. 证据链

评分要能回答「**这一分，证据在哪？**」。证据有四个来源，我们**全都有**：

| 证据源 | 存储 | 服务哪些项 |
|---|---|---|
| 对话原话 | `Message.content`（role=student） | R01–R05, R11–R14 |
| 问句类型 | `Message.intent`（已存 JSON） | R01–R03 的**主动询问**判定 |
| 检查申请轨迹 | `Message.disclosed` 的 `E##.*` 键 | R04 |
| 学员作答 | `student_report` | R06–R10 |

> `Message.intent` 已经落库（`question_type` 在里面），所以「学员是**主动问**出来的，还是开放叙述里顺带得到」
> 是可区分的——这决定了 R01/R02/R03 给 2 分还是 1 分（§7.1）。

## 7. 代码判定详解（R01–R04）

### 7.1 R01–R03：读披露轨迹

`disclosure.gate` 每轮把「本轮允许说的事实」记进 `Message.disclosed`（患者侧存 `["H01","P02"]`）。
**学员问到了什么 = 患者披露了什么**。

```
elicited = ∪(m.disclosed for m in messages if m.role == "patient")  ∩  ^[HP]\d{2}$
R01 = (H01 ∈ elicited) and (H02 ∈ elicited)
R02 = (H03 ∈ elicited) and (H04 ∈ elicited)
R03 = |{H05,H06,H07} ∩ elicited| >= 2     # 医院侧重「相关风险」，不要求三条全中
```

**两个必须处理的边界**：

1. **开放问诊一次给 H01–H04**（`open` 门控扩展 H01–H04）→ R01/R02 会被一次开放问题全部拿满。
   医院原文说这**不算作弊**（「不把正常开放式问诊当作作弊」），所以**给分是对的**，
   但我们要**记录是怎么得到的**（`intent.question_type`），以便标定：主动针对性询问 vs 开放叙述。
2. **已知缺陷**：「预计阴性」问题偶尔漏记披露轨迹 → 学员会被无辜扣分。
   → **判定必须带回退**：`disclosed` 缺失时，用 `intent.asked_facts` 兜底。

### 7.2 R04：读申请轨迹 × 关键项

**已核实的对应关系**：R04 锚点里的必做项 **就是该病例 `level == "关键"` 的 E 项**。
（EN01 的 R04 写「一般口内视诊、36及对照牙冷测叩诊、36根尖片」，对应 E01/E02/E03 三个 `[关键]`；E04 是 `[补充]`，不算。）

```
required = {id for id, e in exam_data.items() if e.level == "关键"}
requested = ∪(E ids parsed from m.disclosed for m in messages if m.role == "exam")
R04 = 逐子锚点：每个 required 项 → 命中 or 未命中
```

**医院的两条约束必须落实**：
- 「**不能因宽召回把整包算成学员已主动选择**」→ 用 `subitem_keys` 区分：
  - 请求命中**整项**（`subitem_keys` 为空）→ 该项算学员申请了；
  - 请求只命中**子项** → 只算该子项；
  - 同时**保存学员请求的原始文本**，供复核。
- 「**复合项目逐子项匹配，不能把冷测、叩诊、视诊互换计分**」→ 见上。

> 这两条我们**已经具备数据基础**：`exam_module` 返回 `exam_ids` + `subitem_keys`，SSE 的 `done` 事件里都有，
> 落库在 `Message.disclosed`。**不需要额外采集。**

## 8. NE / NA / SKIPPED_SAFETY 与安全错误

### 8.1 三个特殊标记（**必须代码判定**）

医院原文（`_docx.txt:99`）：
> 「NE＝因系统/资料无法评价；NA＝本病例/安全早停不适用。**NE/NA 不自动给 0 或满分，同时报告可评上限。**」

| 标记 | 触发条件（代码可判） |
|---|---|
| **NA** | 该病例不存在对应素材。例：某例没有 `[关键]` E 项 → R04 = NA |
| **NE** | 系统侧出问题，学员无从表现。例：会话中途 `error`（`question_type=="error"` 出现）、检查模块连续未提供 |
| **SKIPPED_SAFETY** | SU05 类急救早停例，识别危险后即刻转诊，未跑的常规项（见下） |

**为什么必须代码判**：NE/NA 是**对系统的评价**，不是对学员的评价。
交给 LLM 判，等于让被考核方给自己的失误打分——这正是医院反复强调的
「**系统失败…不得转换为学员失分**」（`_docx.txt:94` 表格）。

### 8.2 SU05 安全早停例（单例特殊规则）

`_docx.txt:5051` 后的专有规则原文：
> 「安全优先例：一旦识别气道/深部感染危险，允许停止非必要问诊、影像和完整常规作答，及时转急救。
> **不能以未跑完清单扣分**；无机会观察的常规项目标 NA/NE 并人工确认。」

→ 识别到危险后未进行的项，标 `SKIPPED_SAFETY`，**不计 0**。识别时机由代码判（哪一轮开始转诊）。

### 8.3 安全错误：独立通道，不参与任何平均

医院原文（`_docx.txt:100`）：
> 「**危及安全的错误另行标记并由教师复核，不与礼貌分平均抵消。**」

每例都有 `关键错误` 行（EN01：「仅凭深龋就承诺必须根管或必然能保髓；以抗生素替代龋病处理」）。
处置：

- 逐条独立判定（LLM + 原话引用），输出 `safety_flags: [{error, hit, evidence_quote}]`；
- **绝不进入 28 分的任何计算，绝不被礼貌分抵消**；
- 命中即在报告顶部**红色置顶**，并标记「需教师复核」。

> **这一条直接判了旧代码的死刑**：`(diagnostic + communication) / 2` 恰恰是在做医院明令禁止的事。

## 9. 报告结构：单一 28 分制 + 两个视图

**不再输出两个 100 分再平均。** 报告形态：

```
┌─ 安全提示（如有）──────────────────────────┐
│ ⚠ 检出关键错误：…（需教师复核，不参与计分）    │
└──────────────────────────────────────────┘
┌─ 临床能力视图（R01–R10）──────────────────┐
│  病史采集   R01 R02 R03      ▓▓▓░  5/6     │
│  检查运用   R04 R05          ▓▓░░  2/4     │
│  诊断与推理 R06 R07 R08      ▓▓▓░  4/6     │
│  处理与计划 R09 R10          ▓▓░░  2/4     │
└──────────────────────────────────────────┘
┌─ 沟通与人文视图（R11–R14）────────────────┐
│  解释与告知 R11 R12          ▓▓▓▓  4/4     │
│  以患者为中心 R13 R14        ▓▓░░  2/4     │
└──────────────────────────────────────────┘
原始分：19 / 28（可评上限 28；NE 0 项，NA 0 项）
```

- **两个视图是同一套 14 项的分组视图**，不是两条独立流水线；
- **不给综合分**。医院没有及格线、权重未定（医生批注），我们不替它发明；
- 若将来需要百分制，就是一次**配置化的加权换算**，权重留 `rubric_common.json` 里待填。

## 11. 验证方案（不等医院也能做的）

评估体系的有效性分两层，**工程层现在就能做，统计层要等医院**。

### 工程层（现在可做）

| # | 手段 | 做法 |
|---|---|---|
| V1 | **锚点覆盖率** | 静态检查：每条 R 有 ≥1 子锚点；每个子锚点的 ref id 在数据中存在 |
| V2 | **隔离回归** | 断言 `answer_key` 不出现在患者 prompt、不出现在学员 API 响应 |
| V3 | **确定性判定的单元验证** | 构造轨迹 → 断言 R01–R04 得分（对标 `run_exam_subitem_tests.py`） |
| V4 | **合成对话回归** | 用医院 **S01 常规路径**（`_docx.txt` B3 段）当**正例**，删步骤造**负例**，断言分数梯度 |
| V5 | **稳定性** | 同输入跑 3 次，看 LLM 判定的方差（对标 B 测试的 3 次制） |

> **V4 是这里最巧妙的一条**：医院写的 `S01 常规路径` 本来就是一条**按 H01→H07→E→P 顺序走完的正规问诊**，
> 天然是「高分参考对话」；`S02 顺序变化与干扰路径` 天然是「压力测试」。**我们不用自己编标准答案。**

### 统计层（需医院，文档已留位）

| # | 手段 | 目标 |
|---|---|---|
| V6 | **人工一致性** | 3 位老师独立评同一批记录，算 ICC / Cohen's κ / Pearson r |
| V7 | **LLM vs 人工一致性** | 同批记录 LLM 评分对照老师评分 |
| V8 | **判别力** | 高/低分脚本能否被系统分开 |

A3 页底部已有现成的格子：`审阅者1：____ 审阅者2：____ 分歧/裁决：____ 定版日期：____`
——**一致性实验的表格医院已经画好了，只是没人填。**

> 诚实声明：V6–V8 **我们一条都还没有**。医院侧现为 0 条真实学员记录、0 条专家评分。
> 目标值 ICC≥0.75 / r≥0.80 **是我们自己定的**，不是医院的。

## 12. 边界与不做

- ❌ **不做病历书写评估**——医院明确「不含完整病历书写和真实操作」（`_docx.txt:7`）
- ❌ **不评估真实操作**（无模拟人、无器械）——本系统只有文字
- ❌ **不发明及格线、不发明权重**——医院未定，我们填 `null` 并在报告里标注
- ❌ **不取平均**——§8.3
- ❌ **不做 C / D 类数据实验**——那要真人，超出本阶段
- ⏸ **不做 30 例之外的扩展**——先 5 例跑通，与数据切分节奏一致
