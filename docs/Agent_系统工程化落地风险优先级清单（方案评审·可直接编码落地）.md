# Agent 系统工程化落地风险优先级清单（方案评审·可直接编码落地）

## 0\. 清单说明

- **适用场景**：Agent项目立项评审、架构方案评审、上线准入、迭代变更评审、vibe coding 约束校验

- **风险分级**

    - P0（一票否决/高危）：存在即禁止上线，直接造成业务故障、资损、合规事故、数据泄露

    - P1（高风险）：必须迭代解决，否则稳定性/可用性不达标，无法规模化落地

    - P2（中风险）：上线可容忍，需限期整改，规避边界case累积问题

    - P3（低风险）：体验、成本、优化类问题，不影响核心业务交付

- **编码落地适配**：每条风险附带「工程约束/代码落地点」，可直接转为校验规则、拦截器、监控告警、状态机配置

## 1\. P0 一票否决风险（上线必过，任意不满足直接打回）

核心原则：安全、权限、合规、不可回滚操作、强资损场景无兜底，禁止投产

|风险编号|风险描述|危害后果|工程落地约束（可直接编码）|整改标准|
|---|---|---|---|---|
|P0\-01|Agent 拥有高权限账号，未做最小权限隔离，可直接执行写库、删数据、资金操作、权限变更|越权操作、数据损毁、直接资损、系统故障|所有工具接口强制权限白名单；读写分离；高危操作单独开关；禁止复用自然人账号|高危写操作必须有人工审批/熔断开关，权限可审计、可追溯|
|P0\-02|未做 Prompt 注入、间接注入防护，外部不可信内容可劫持 Agent 决策与工具调用|恶意指令执行、数据窃取、违规调用接口、业务篡改|输入清洗、指令隔离、系统Prompt防覆盖、工具调用参数强校验、红队对抗测试|通过注入专项测试，存在强制拦截策略|
|P0\-03|敏感数据（用户隐私、业务机密、医疗/政务数据）无分级脱敏，直接送入大模型公网接口|合规违规、数据泄露、行政处罚、舆情风险|数据分级、前置脱敏、敏感字段掩码、禁止核心机密数据出境/公网调用|全链路脱敏可审计，无明文敏感数据入模型|
|P0\-04|高风险决策场景（资金、审核、诊断、人事、法务）全自动无人工兜底|批量错误决策、重大业务事故、责任无法界定|高风险动作强制人机交接、阈值拦截、结果复核、熔断降级|高危场景100%可人工介入，无纯全自动高风险操作|
|P0\-05|无完整审计链路，无法追溯思考过程、工具调用、入参出参、决策依据|事故无法复盘、无法定责、不满足企业合规与等保要求|全链路日志：prompt、thought、tool\_call、tool\_result、final\_resp、耗时、token、版本|每一次Agent动作可完整追溯、可回放、可导出审计报告|
|P0\-06|无紧急关停/熔断开关，Agent失控（循环调用、风暴、越权）无法快速终止|算力打爆、接口雪崩、业务持续受损、故障扩大|全局Kill开关、单任务强制终止、最大轮次限制、频次限流、异常自动熔断|1分钟内可完全关停Agent所有自动执行动作|

## 2\. P1 高风险（必须上线前解决，规模化阻断项）

|风险编号|风险描述|危害后果|工程落地约束（可直接编码）|整改标准|
|---|---|---|---|---|
|P1\-01|工具调用无强结构化校验，JSON报错、字段缺失、参数类型错误导致批量失败|任务失败率高、用户体验极差、人工兜底压力大|JSON Schema 强制校验、参数必填校验、类型转换容错、自动重试\+失败降级|工具调用格式错误率趋近于0，异常可自动降级|
|P1\-02|存在工具调用风暴、死循环、重复调用同一工具，无轮次/频次限制|成本暴增、时延超限、接口限流、服务雪崩|单任务最大轮次限制、重复调用检测、相同参数幂等拦截、超时强制终止|杜绝无效循环调用，轮次可控、成本可预测|
|P1\-03|任务无状态持久化，重启/超时/崩溃后任务从头执行，无法断点续跑|重复执行、重复下单/重复通知、数据不一致、用户投诉|状态机驱动（LangGraph/Temporal）、阶段快照、进度持久化、幂等执行|异常中断后可断点续跑，无重复执行副作用|
|P1\-04|记忆系统无管控：向量召回污染、记忆中毒、无效信息堆叠、上下文溢出|幻觉严重、答案失真、任务跑偏、越长越错|记忆分级（瞬时/短期/长期）、权重打分、过期清理、去重、截断策略可控|记忆可清理、可归档、可过期，召回精准度可控|
|P1\-05|LLM 输出无校验，幻觉、虚构数据、错误结论直接对外输出|业务错误、误导用户、专业场景事故|事实校验、引用溯源、输出合规校验、关键结论二次复核prompt|关键输出必须可溯源，无虚构事实输出|
|P1\-06|多Agent协同无分工、无仲裁、无标准通信协议，信息不对称、决策冲突|协同混乱、任务卡死、结果矛盾、自动化率上不去|角色职责固化、统一消息协议、冲突仲裁策略、结果收敛机制|多Agent任务可稳定收敛，无死锁、无无效拉扯|

## 3\. P2 中风险（上线可放行，迭代期必须整改）

|风险编号|风险描述|危害后果|工程落地约束（可直接编码）|整改标准|
|---|---|---|---|---|
|P2\-01|无标准化指标体系，无法量化任务完成率、幻觉率、轮次效率、失败率|无法评估迭代效果、优化无方向、全靠体感|埋点指标：成功率、轮次分布、token消耗、失败原因分类、幻觉抽检率|核心指标可大盘观测、可对比迭代|
|P2\-02|Prompt/技能无版本管理、无A/B测试，变更不可控、回滚困难|迭代翻车、退化无法定位、线上行为突变|Prompt版本Git管理、技能版本绑定、灰度发布、快速回滚机制|所有变更可追溯、可灰度、可回滚|
|P2\-03|异常场景覆盖不足，仅适配标准流程，边界case直接失败|极端场景用户体验差、自动化覆盖率低|异常分支枚举、兜底话术、异常分类降级、超时/重试策略细化|已知异常均有兜底，不直接崩溃|
|P2\-04|人机协同点位缺失，该转人工不转、不该转人工乱转|自动化率低、人工成本高、用户体验割裂|明确人机交接阈值：信息不足、风险过高、连续失败、超时兜底|人机切换策略清晰，可量化自动化率|

## 4\. P3 低风险（体验/成本优化，不阻塞上线）

|风险编号|风险描述|优化方向（可迭代落地）|
|---|---|---|
|P3\-01|端到端时延波动大，峰值响应慢|模型选型优化、缓存、并行调用、prompt精简、轮次压缩|
|P3\-02|Token成本不可控、浪费较多|上下文智能截断、冗余内容过滤、模型分级调用（小模型处理简单任务）|
|P3\-03|输出风格不统一、话术不稳定|输出格式约束、风格模板、后处理统一润色|
|P3\-04|业务知识库迭代效率低|知识库自动化更新、增量索引、定期巡检清洗|

## 5\. 评审结论规则（自动化判定逻辑，可直接写评审脚本）

- **禁止上线**：任意 P0 风险未闭环

- **受限试点**：P1 存在未闭环，仅允许小流量灰度、只读、无资损场景

- **可全量上线**：P0/P1 全部闭环，P2/P3 有明确整改计划

## 6\. 极简落地编码范式（vibe coding 专用约束）

所有Agent工程实现必须默认嵌入以下四层防护，作为代码基线：

1. **权限层**：最小权限 \+ 高危操作开关 \+ 操作审计

2. **输入层**：清洗过滤 \+ 防注入 \+ 参数校验

3. **执行层**：状态机管控 \+ 最大轮次 \+ 超时熔断 \+ 幂等

4. **输出层**：事实校验 \+ 合规校验 \+ 人机兜底 \+ 全链路日志
