# 定位与原则重述

> 回答一个根本问题：**我们到底在做什么？** 以及做它必须遵守的几条原则。
> 写于 2026-10-09，作为后续所有开发决策的参照。刻意简短——只定原则，不定细节。

## 1. 定位

**我们做的不是"口腔问答系统"，而是"标准化患者（SP）模拟引擎，口腔先行"。**

- **引擎** = 一套可复用的架构（人格 + 披露门控 + 数据边界 + 校验），与科室无关。
- **口腔** = 第一个、也是当前唯一的实例，用它来验证引擎是否成立。

一句话：**同一个引擎，换一份专家写的数据，就能扮演另一个科室的患者。** 这是目标，但它的成本见 §4。

## 2. 五条原则（按优先级）

### P1 忠实优先于聪明（地板）
开发者无医学背景。患者说出的每个医学事实，必须能追溯到数据集原文。宁可少说、说"没太注意"，也不编造、不"合理推断"。

### P2 脚本是骨架，即兴是血肉（天花板）
医学事实和披露规则**锁死**（来自数据），语言表达**放开**（语气、犹豫、衔接、反问）。内容忠实、表达可优化。

> **忠实是地板，逼真是目标。** 只有地板没有目标 → 僵硬的问答系统；只想目标不要地板 → 幻觉，危害教学。两条必须同时成立。

### P3 引擎 / 内容分离
凡是科室特有的（事实槽、检查项、评分条目、牙位表达），一律做进**数据/配置**，不写进代码。这是泛化的唯一前提，也是"数据解耦"的真正理由。

### P4 边界结构化，不靠 prompt 自觉
- 不泄露诊断/治疗 → **数据边界**（患者侧根本没有答案，而非"被告知别说"）。
- 不过度披露 → **披露门控**（结构性裁剪，而非"提醒模型别倒太多"）。

### P5 B 测试即规格
B01–B12 不是验收，是**开发时的规格**：照着它写、照着它调、用它回归。行为对不对，用断言（ID 是否命中），不用人读文本猜。

## 3. 当前边界

**现在做**：患者对话模拟（H/P + 开场白 + 披露 + 记忆），5 例，跑通核心。
**现在不做**：检查模块（后置到前端形态）、评分、评价器、persona 81 组合、前端改动、全 30 例批量切分。

## 4. 泛化的边界与成本（诚实版）

| 项 | 泛化情况 |
|---|---|
| 引擎（架构） | ✅ 可复用 |
| 数据 schema 结构（H/P/E/D/R/B） | ✅ 结构可复用 |
| 行为规则（缺失≠阴性、抗错误前提、P03） | ✅ 基本通用 |
| 事实槽内容、检查项、评分条目 | ❌ **每个科室由专家重写** |
| 牙位编号等口腔特有表达 | ❌ 需参数化或替换 |

**成本**：泛化不是免费的。每增加一个科室 = 一份专家撰写的数据 + 一套评分 + 一套行为测试 + 一轮验证。我们能复用的是**工程部分**，医学部分永远是新的专家工作量。

**因此**：当前不构建抽象框架，只做口腔实例，但**把引擎/内容的缝留干净**。等第二个科室真正落地，才证明引擎真的通用——在那之前，"泛化"是一条纪律和一个假设，不是已证能力。

## 5. 非目标

- 不是医学专家系统（不诊断、不给诊疗建议）。
- 不是通用聊天机器人（只能演数据集里的患者）。
- 不是"自动生成其他科室病例"的流水线（内容必须专家写）。
- 不是一次性做完所有科室（口腔先跑通，再谈扩展）。
