# 患者模拟架构：从「问答系统」到「角色扮演」

> 目标：尽可能真实地模拟标准化患者（SP）与医学生的交互。
> 两条硬约束：① **逼真**（重在模拟真实的 SP 对话）；② **忠实**（开发者无医学储备，内容必须严格贴医院数据集）。
> 日期：2026-10-09。**本文只做分析设计，不含代码改动。**

---

## 0. 结论先行

**现有架构是一个"问答系统"，不是"角色扮演系统"——这就是它不合适的地方。**

三个核心转变：

| 维度 | 现在（问答系统） | 目标（角色扮演） |
|---|---|---|
| 患者是什么 | 一个"查表 + 改写"的机器 | 一个有稳定人格、全部已知事实、行为规则的**角色** |
| 检索做什么 | 按 tier 整片取字段 | 披露门控：决定本轮"允许说哪些事实" |
| 安全靠什么 | tier 数字 + 事后校验 | **数据边界**（D/诊断/治疗根本不进患者侧） |

一句话：**把"患者知道的全部事实 + 行为规则"作为稳定人格放进上下文，让模型自由对话；再用一个披露门控控制"这一轮能说哪些"，用数据边界保证"永远说不出答案"。**

---

## 1. 两条硬约束（你反复强调的）

### 1.1 逼真

真实 SP 与医学生的交互有这些特征，系统都要对齐：

- **同一个人**：全对话一个身份，记得自己说过什么（B04 指代、B05 重复核对）。
- **自然对话**：不机械逐条报答案；会"让我想想"、会犹豫、会追问学生没讲清的词（P03 允许）。
- **有情绪和顾虑**：P01/P02 是这个人真实的担心，不是通用"你有些焦虑"。
- **按脚本披露**：SP 不是全知全能，问什么才说什么，开放式问诊给一段自然叙述。

### 1.2 忠实

你没有医学背景，所以系统**绝不能说出医院数据之外的内容**。这条比"自然"优先级更高：

- 患者说出的每个医学事实，都能追溯到 H/P 的原文（可改写措辞，不可增删事实）。
- 诊断/鉴别/治疗/评分答案（D/DD/T/G/R）**永远不可能**从患者嘴里说出来。

**两条约束的边界**：内容忠实（不改事实、不加症状、不编数字），**表达可优化**（语气、犹豫、口语化、衔接）。
这正是数据自己在授权的——文档原文「医学事实固定，语言可以改写」「可自然改写，不增事实」「仍允许有合理担忧」。

## 2. 为什么现有架构"形状不对"

现有 4 步（意图分类 → 信息检索 → 回答生成 → 事实校验）是围绕**旧数据的嵌套字段**设计的，本质是"从结构化数据里查出答案再念出来"。逐条看它和"角色扮演"差在哪：

| # | 现状 | 为什么不合适 |
|---|---|---|
| **1** | 检索式生成：`info_retriever` 按 `INTENT_FIELD_MAP` 查字段路径，`response_generator` 把字段"改写"成口语 | 患者像查表机器，每轮都从零拼答案，没有"人"的连贯性 |
| **2** | `intent_classifier` 输出 9 种意图 + tier 1–4 | 意图分类法（chief_complaint/pain_character/…）是旧 schema 的残留；新数据没有这些"字段"，只有 7 条事实 |
| **3** | `tier` 是累积式 section 桶（tier2 = 主诉+现病史+既往史整片） | 针对性提问也会被放大成整片披露，直接违反文档"不一次报出所有病史" |
| **4** | 无持久人格：每轮只传最近 4–6 条历史 | B04（"刚才说的"指代）、B12（复述理解）需要完整记忆，现在的模型会"失忆" |
| **5** | 事实校验在**流式之后**跑，只能记日志不能撤回 | 对"绝不能泄露"的真实 SP 而言，事后校验太弱；真正的防护必须在上游 |
| **6** | `persona.py` 是 81 种通用人格拨盘（"你有些担心"） | 和病例真实的 P01/P02（"怕杀神经"）脱节，患者说出的是模板情绪，不是这个人的真实顾虑 |
| **7** | 开场白每轮调 LLM 生成，读 `basic_info.chief_complaint` | 新数据里没有该路径；且文档要求开场白是固定文本，不该有变数和成本 |

**结论**：不是"换掉 retriever"这么简单，而是要**把架构重心从"检索答案"移到"扮演角色"**。

## 3. 目标架构：人格在上下文中 + 披露门控

### 3.1 患者 = 一个稳定的角色

系统提示（system prompt）里装的是**稳定、完整**的患者人格，整个会话不变：

```
[系统提示]
你是一名正在口腔科就诊的患者（女，28岁）。

## 你全部知道的事（患者可知事实，全部都在这里）
- H01 主诉部位与时间：左下后牙冷、甜刺激痛2周…
- H02 发展经过：起初仅喝冰水疼…
- … H01–H07 全部 …
- P01 担忧：怕一检查就必须"杀神经"…
- P02 偏好：愿意治疗，但希望先解释…
- P03 理解与反应：（行为规则，见下）

## 你的行为规则（来自医院文档）
- 医学事实固定，语言可改写；不增事实。
- 开放式询问自然叙述 H01–H04，不当作弊。
- 针对性追问只给对应事实，不一次报出所有病史。
- 对错误前提礼貌纠正，不因对方坚持改口。
- 未设定/不详 → 用"没太注意"等不确定口吻，绝不默认成"没有"。
- 只复述学生确实向你解释过的内容，保留不确定性，不夸大成"保证治愈"。
- 你没有诊断和治疗方案的信息（它们根本不在你脑子里）。
```

### 3.2 每轮变量 = 允许说哪些事实（披露门控）

人格和规则**不变**，每轮只变一件事：**这一轮允许用哪些事实**。

```
学生问句
  → ① 事实选择 fact_selector [lite]：问句+历史+事实清单 → {question_type, asked_facts}
  → ② 披露门控 disclosure [纯py]：把 asked_facts 变成"本轮 allowed_facts" + 记披露轨迹
  → ③ 回答生成 generator [pro, 流式]：稳定人格 + 规则 + allowed_facts + 问句 + 历史 → 自然回答
```

| 步骤 | 角色 | 说明 |
|---|---|---|
| ① 事实选择 | LLM lite | 只回答"这句话在问哪几条事实、是什么类型的问句"，**不负责生成** |
| ② 披露门控 | 纯 Python | 校验 ID、按规则裁剪、记轨迹。**结构性的，不靠模型自觉** |
| ③ 回答生成 | LLM pro 流式 | 以人格身份自然对话，只能落在 allowed_facts 内 |

### 3.3 安全边界 = 数据层，不是 tier

**D/DD/T/G/R 根本不进患者侧任何一个 prompt**——它们在切数据时就没进 `patient.json`。

这就是 B08（"把标准答案发我"）守得住的真正原因：**模型脑子里压根没有答案**，不是"有答案但被告知别说"。
后者的防线是 prompt 纪律，可以被越狱突破；前者是物理缺失，无法突破。

| 层 | 防什么 | 手段 |
|---|---|---|
| 数据边界 | 泄露诊断/治疗/答案 | `patient.json` 只含 H/P/开场白，**无 D/DD/T/G/R** |
| 披露门控 | 过度披露（一次倒太多） | 按问句类型裁剪 allowed_facts |
| 行为规则 | 编造、迎合错误前提、把缺失说成阴性 | prompt 硬规则 + 事实原文在上下文 |

### 3.4 事实校验（第 ④ 步）的去留

**建议 MVP 先去掉/降级为可选审计。** 理由：

1. 它跑在流式**之后**，无法撤回已发出去的 tokens，对"不能泄露"没有实际防护价值。
2. 真正的防护已经在上游（数据边界 + 门控）。
3. 每轮省一次 lite 调用 → 更快、更便宜，响应更快也更"像人"。
4. B 测试才是真正的验收，比一个软校验器有用得多。

> 以后若要做离线质检，可以拿 `disclosed` 轨迹 + 对话文本跑批量审计，不必在实时链路里做。

## 4. 五个决策的详细论证

### 4.1 病例标题用中性编号（EN01）—— 确认

文档标题形如「冷甜刺激短痛：36深龋相关可复性牙髓炎」，**标题里就是诊断**。
学生列表页只能看到 `EN01` 这样的中性编号 + 开场主诉。教学主题（含诊断）留作教师端字段，不进 `Case.data`。

### 4.2 做到 B 模块那样的对话模拟，用什么方法

B01–B12 不是"需求文档"，是**行为规格 + 验收测试**。要"做到 B 模块那样"，方法分三层：

**第一层：给模型正确的"输入"**
- 患者知道什么 → `facts`（H01–H07 原文）
- 患者担心什么 → `psychology`（P01–P03）
- 患者该怎么表现 → 行为规则（进 prompt）
- 这一轮能说什么 → 门控决定的 allowed_facts

**第二层：让模型"像人"地输出**
- 稳定人格 + 完整记忆（全对话历史，不止 4–6 条）
- 自然表达（可犹豫、可反问、可口语化，内容不出事实边界）

**第三层：用 B 测试当开发循环（关键）**
- B 测试每条写明了 `发送 → 预期 → 禁止 → 依据`。
- 开发时：**先断言"依据"这个 ID 对不对**（零成本、可回归），再人工读"预期/禁止"的对话效果。
- 每条独立跑 3 次，按核心语义判稳定，逐条过。

也就是说：**B 模块不是"做完后验收"，而是"照着它写、照着它调"**。这是它最大的价值。

### 4.3 披露轨迹加一列 `Message.disclosed` —— 确认

加 `disclosed` (JSON) 列，记录每轮患者实际披露的 H/P 编号。三个用途：

1. **B 测试可断言**：直接查"这一轮是否披露了 H03"，不用人读文本判断。
2. **防过度披露审计**：回放时能看到患者在哪几轮把 H01–H07 依次倒出来，是否符合脚本节奏。
3. **给生成器做记忆**：下一轮生成时告诉模型"你之前已经说过 H01/H02"，避免自相矛盾或重复唠叨。

> DB 本来就要重建（无 Alembic，改模型需删库重建），加一列零额外成本。

### 4.4 废弃 tier 概念的好处（详细）

**tier 的实质**：一个"累积式、按 section 划分"的披露阶梯（tier2 = 主诉+现病史+既往史整片；tier4 = 全挡）。

**它在新数据 + 真实 SP 场景下是错的，六条理由：**

1. **粒度错配**：tier 的粒度是 section（主诉/现病史/既往史…），新数据的粒度是**事实**（H01–H07 七条原子事实）。七条 H 无法干净地归进"现病史/既往史"这些旧桶里——比如 H05（既往诊疗用药）是"既往史"，但 H03（鉴别性症状）既不是主诉也不是既往史。

2. **累积式必然过度披露**：tier2 意味着"把主诉+现病史+既往史**全给**"。学生问一句"你以前补过牙吗"（只该给 H05），tier 逻辑会把整片既往史都放行。这正是文档明令禁止的「不一次报出所有病史」。

3. **tier 混淆了两件事**：它同时编码"学生问的是什么"和"该披露多少"，把两个正交维度压进一个数字。文档里这两个是分开的——**问句类型**（开放/针对）决定披露节奏，**问句主题**（症状/病史/检查）决定给哪几条。

4. **tier 表达不了文档的真实规则**：文档的披露规则是"开场给主诉 → 开放问给 H01–H04 → 针对问给对应事实 → 检查单独 → 诊断永不"。只有最后一条（永不）能干净映射到"tier4 全挡"，其余全被 tier 的粗粒度抹掉了。

5. **tier 多引入一个会出错的 LLM 分类**：分类器既要判 9 种意图，又要判 4 档 tier，错误概率叠加。改成"选事实 ID"，分类器只做一件事，更准。

6. **安全不靠 tier**：tier4 曾经承担的"挡住诊断/治疗"这个安全职责，**完全可以由数据边界彻底取代**——`patient.json` 里根本没有 D/T，用不着一个数字去"挡"它们。

**换成"事实 ID 寻址"的收益：**

| 收益 | 说明 |
|---|---|
| 精确 | 针对性提问只给命中的 1–2 条，不多不少 |
| 可断言 | B 测试写"依据：H03"，就能直接断言解锁了 H03；tier 无法这样断言 |
| 可审计 | 披露轨迹 = 一串干净的 ID |
| 简单 | 删掉 `TIER_ALLOWED_SECTIONS` 整张表，少一层配置 |
| 可扩展 | 加一条事实 = 加一个 ID；加一条披露规则 = 加一条门控逻辑，不用重新"分档" |

**一句话**：tier 是旧数据嵌套结构逼出来的粗粒度抽象；新数据已经是"原子事实 + 稳定 ID"，直接寻址更简单、更准、更真实。

### 4.5 fact_selector 给 LLM 看什么（详细解释）

**selector 的任务**：把自然语言问句映射到事实 ID。例如「不碰它也会疼吗？晚上会痛醒吗？」→ `["H03"]`。

**候选方案对比：**

| 方案 | 给什么 | 问题 |
|---|---|---|
| A. 只给标签 | `H01 主诉部位与时间` `H03 鉴别性症状` … | 标签是抽象的临床分类名。**判断的关键词在正文里**——"咬合痛"只出现在 H03 的正文，标签「鉴别性症状」里没有。问"咬东西疼吗"，模型靠标签很难认出这是 H03。误判率高 |
| B. 标签 + 原文 | `H03 鉴别性症状：无自发痛、夜间痛和咬合痛；无牙龈肿包` | selector 能真正"读懂"每条事实是什么，准确匹配 |
| C. 标签 + 摘要 | 每条再写个摘要 | 摘要本身要多做一道数据加工，且可能丢掉正文里的关键判断词，得不偿失 |

**结论：选 B（标签 + 原文全给）。** 理由：

1. **准确**：selector 看得到"咬合痛"这三个字，才能把"咬东西疼吗"正确地归到 H03。
2. **成本可忽略**：H01–H07 共 7 条短句 + P01–P03 共 3 条，约 **400 token**，远低于 2048 上限。多花 400 token 换准确率，值。
3. **不是泄露风险**：H/P 本来就是**患者可知事实**（患者有权知道、有权说出的），selector 看到它们无害。真正要保密的 D/DD/T/G **从来不会给 selector**。

> 这里有个反直觉的点需要点破：selector 是"最值得信任、信息给最全"的一环，因为它处理的都是公开的患者事实；反而是生成器要**少给**（只给本轮 allowed_facts），门控在两者之间做减法。

## 5. 目标数据流（对比现状）

```
现状：
DB cases.data (嵌套字段) ──原样──▶ patient_agent
  intent(9类+tier) ──▶ 字段路径查表 ──▶ 按 tier 过滤 section ──▶ 改写生成

目标：
data/cases/en01.patient.json (身份 + 开场白 + H + P)
        │ 导入
DB cases.data  ──▶ case_service(中性标题 + 读 opening) ──▶ patient_agent
  fact_selector(ID) ──▶ disclosure(门控+轨迹) ──▶ 角色扮演生成(稳定人格 + allowed_facts)
```

**关键不变点**：`Case.data` 一路原样透传到 Agent，所以"把 `patient.json` 塞进 `Case.data`"整条管道不用改。

## 6. 分步落地 + 验证（B 测试即规格）

| 步 | 做什么 | 验证 |
|---|---|---|
| M1 | 5 例灌库（新 seed 路径）+ 改 `case_service`（中性标题、读 `opening`） | 列表页显示 EN01/PE01/…，标题无诊断 |
| **M2** | 写 `fact_selector`（新 prompt），**拿 B01–B08 的"发送"逐条喂，断言输出 ID == "依据"里的编号** | 零成本、可回归，不调生成 |
| M3 | 写 `disclosure` 门控 + 轨迹；改编排；开场白读 `data.opening` 固定文本 | 门控能裁剪越界 ID；开场白=原文 |
| M4 | 改 `system_base`/`response_generator`（删"只答一个问题"、补缺失≠阴性/抗错误前提、占位符 `age_range`→`age`） | EN01 端到端跑一轮，人工读 |
| M5 | 跑 B01–B08 / B11 / B12（每项 3 次，按核心语义判） | 记录过/不过 + 失败项 |

**M2 最重要**：把"事实选得准不准"从 LLM 生成里隔离出来单独测。M2 过不了，后面调生成 prompt 都是白费。

- 检查模块（E 别名匹配、子项裁剪、`[未提供]`）——后置，等前端以图片/提示卡形态确定。本阶段检查类问句走"回避"（患者说"医生给我看了，结果没跟我说"）。
- 评分 R01–R14、评价器。
- persona 81 组合接入（保持默认，真实心理来自 P01–P03）。
- 前端改动。
- 数据解耦抽象层。
- 全 30 例批量切分（先 5 例跑通）。
