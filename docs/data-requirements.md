# 数据需求：这个系统到底需要什么样的数据

> 写于 2026-10-11。**先讲需求，再定结构**——范本见 [case-data-schema.md](case-data-schema.md)。
> 医院的 30 例 docx 是"素材"，不是"成品"；本文回答的是：**我们的系统需要从中取出什么、按什么层级组织**。
> 与 [positioning-and-principles.md](positioning-and-principles.md) 的 P1（忠实）、P3（引擎/内容分离）、P4（边界结构化）直接相关。

---

## 1. 先问：系统里有几个"说话的角色"

数据需求不是凭空定的，是从**谁要用这些数据说话**倒推的。

| 角色 | 它要说的话 | 它**绝不能**说的 | 谁在听 |
|---|---|---|---|
| **患者** | 自己的症状、病史、担忧、感受 | 检查结果、诊断、治疗方案、评分标准 | 学生 |
| **检查模块** | 某项检查的文字结果（数据原文） | 患者的主观感受、诊断、治疗方案 | 学生 |
| **评估器** | 分数、评语、遗漏项 | （不对学生说话） | 教师/系统 |
| **教师端** | 教学目标、标准答案、行为测试 | （不给学生看） | 教师 |

**这就是为什么数据必须按"谁能看见"来分，而不是按"文档里怎么排的"来分。**
患者 Agent 拿不到检查结果，检查模块拿不到患者事实——这不是靠提示词约束，是**数据里就没有**。

---

## 2. 标签层级：四层

医院的编号体系（H/P/E/D/DD/T/G/R/B/S/K/V）本身已经隐含了层级，我们把它**显式化**为四层：

```
第 1 层  权限层   —— 谁能看见        （患者侧 / 检查侧 / 教师侧 / 开发期测试）
第 2 层  模块层   —— 是哪一类信息     （事实 H / 心理 P / 检查 E / 诊断 D …）
第 3 层  项层     —— 具体哪一条       （H01、H02、E01、E02 …）
第 4 层  子项层   —— 项内部的分段     （E02 里的「冷测」「叩诊」「松动度」）
```

### 第 1 层：权限层（**最重要**）

| 层 | 编号 | 进哪个文件 | 理由 |
|---|---|---|---|
| 患者侧 | `H`、`P` + 身份 + 开场白 | `patient.json` | 患者有权知道、有权说出 |
| 检查侧 | `E` | `exam.json` | 只有学生**申请后**才返回；患者本人不会背检查结果 |
| 教师侧 | `D`/`DD`/`T`/`G`/`R`/`K`/`V` | **不入产品数据** | 标准答案。学生必须自己推导，系统永不透露 |
| 开发期 | `B`、`S` | `data/tests/` | 不是病例内容，是**规格与验收**（P5） |

> **P4 的落点**：不泄露诊断，靠的是"患者侧数据里根本没有 D/T"，而不是"提示模型别说"。
> 前者是物理缺失、越狱也突破不了；后者是纪律、可以被绕过。

### 第 2 层：模块层

| 模块 | 医院编号 | 我们是否现在用 | 说明 |
|---|---|---|---|
| 患者事实 | `H01`–`H07` | ✅ 用 | 7 条原子事实，固定槽位 |
| 心理与理解 | `P01`–`P03` | ✅ 用 | 担忧 / 偏好 / 理解与反应 |
| 检查项 | `E01`–`E0n` | ✅ 用 | 见下 |
| 诊断/鉴别/计划/沟通 | `D`/`DD`/`T`/`G` | ⏸ 暂不用 | 留给评估模块 |
| 评分条目 | `R01`–`R14` | ⏸ 暂不用 | 留给评分模块 |
| 医学依据/参考文献 | `K`/`V` | ⏸ 暂不用 | 教师端用 |

### 第 3 层：项层

- **患者侧**：`H01`–`H07` **槽位固定**（七条语义固定：主诉/发展/鉴别/危险征象/既往/全身/习惯）。
  固定槽位是泛化的前提——换科室时槽位名不变、内容换。
- **检查侧**：`E01`–`E0n` **数量可变**，每例 3–5 项，由医院按病例决定。

### 第 4 层：子项层（**当前正在补的一层**）

这是唯一一层医院**写得时有时无**的。结构长这样：

```
E02  36及对照牙冷测、叩诊                    ← 项（学生的"申请单位"）
 ├ 子项「冷测」                             ← 子项（学生可能只申请这一小项）
 │   ├ 别名组：冷诊 / 冷测 / 冷刺激试验 / …   ← 学生可能怎么问
 │   └ 结果片段："36冷测痛约3秒消失；…"       ← 只返回这一句
 ├ 子项「叩诊」
 │   ├ 别名组：叩诊 / 叩痛检查 / …
 │   └ 结果片段："36叩诊阴性"
 ├ 子项「松动度」
 │   ├ 别名组：检查松动度 / 牙齿活动度检查
 │   └ 结果片段："松动度0。"
 └ 子项「牙髓活力」（伞形）                   ← 问它返回整包
     └ 别名组：牙髓检查 / 牙髓活力测试 / …
     └ 结果片段：null
```

**为什么需要子项层？** 因为医院在规则里明确要求：

> 相关子项请求仅返回该项结果，不可返回整个 E 项（如仅询问冷诊，不可同时返回叩诊结果）

现实里学生只说"我做个冷测"，检查室不会顺手把叩诊和松动度也报给他。**整包返回既不真实，也让学生不用开口就拿到没申请的信息。**

## 3. 每个角色具体需要哪些字段

### 患者侧（`patient.json`）

| 字段 | 内容 | 从哪来 |
|---|---|---|
| `identity` | 性别、年龄 | 医院文档（身份设定） |
| `opening` | 开场白（固定文本） | **医院原文**，逐字不改 |
| `facts.H01–H07` | 每条：`label`（槽位名）+ `text`（原文） | 医院原文 |
| `psychology.P01–P03` | 同上 | 医院原文 |

- `label`（槽位名）**是给选择器看的**——它只读标签认不出"咬合痛"，必须看 `text`（见 [patient-roleplay-architecture.md](patient-roleplay-architecture.md) §4.5）。
- `text` **逐字不可改**（P1）。患者可以说得口语化，那是生成阶段的事，数据层不许动。

### 检查侧（`exam.json`）

| 字段 | 内容 | 从哪来 |
|---|---|---|
| `label` | 项名 | 医院原文 |
| `level` | `关键`/`条件性`/`补充`/`未提供` | 医院原文 |
| `result` | 该检查的文字结果（**原文，永不改动**） | 医院原文 |
| `boundary` | 规则说明 | 医院原文 |
| `subitems[].label` | 子项名 | 医院写的 / **我们补的** |
| `subitems[].aliases` | 该子项的别名 | 医院原文（分组即子项） |
| `subitems[].result_fragment` | 该子项对应的结果片段 | **我们切分** |
| `subitems[].source` | `authored` / `derived` | **标记来源，用于事后复核** |

`level = 未提供` 表示"这项检查登记在册但没有结果"（如 MU01 的血常规）——问它必须答"未提供"，不能说"正常"。

### 教师侧

`D`/`DD`/`T`/`G`/`R`/`K`/`V` **现在不取**。将来评估模块要用时，同样按"权限层"单独成文件，绝不混进患者侧。

## 4. 医院的素材 vs 我们的成品（差在哪）

| 维度 | 医院 docx | 我们的成品 | 谁来做 |
|---|---|---|---|
| 编号体系 | ✅ 有（但混在一份文档里） | 按权限层拆成多个文件 | **我们切** |
| 患者事实原文 | ✅ 有 | 逐字搬运 | 我们切 |
| 开场白 | ✅ 有 | 逐字搬运 | 我们切 |
| 检查项 | ✅ 有 | 逐字搬运 | 我们切 |
| **检查子项** | ⚠️ **分组时有时无、组名常缺失** | 完整子项 + 结果片段 | **需要我们补**（当前工作） |
| 行为测试 | ✅ 有（B/S） | 转成可断言的 JSON | 我们切 |
| 权限规则 | ✅ 文字描述 | 落到文件边界上 | 我们落 |

**只有一格需要"补内容"**：检查子项。其余全是"搬运 + 重新组织"。
这也说明当前这一步的性质：**不是加工医学内容，是恢复结构 + 补元数据**。

---

## 5. 补子项的界限（P1 红线）

补子项时**允许做**与**禁止做**：

| ✅ 允许 | ❌ 禁止 |
|---|---|
| 给已有的别名组起名（名字要能在该组别名里找到依据） | 发明医院没写的检查、结果、数值 |
| 决定"结果的哪一句属于哪个子项" | **改写、润色、合并、精简结果文字** |
| 标记 `source: derived` | 丢掉任何一句结果 |

**机器护栏**（见 [case-data-schema.md](case-data-schema.md) §校验规则）：
1. 每个片段必须是 `result` 的**逐字连续子串**
2. 所有片段拼起来必须能**还原整条 `result`**
3. 子项名必须在该组别名里**有出处**

任一不过 → 该项不切分、整包返回、记入待人工清单。**宁可少做，不可做错。**

> 这样就不违反 P1：片段逐字就是原文，我们补的是**结构**（哪句属于哪一小项），那是元数据，不是医学内容。

---

## 6. 对医院方的需求（后置，不阻塞开发）

现在不打扰医院，但将来需要他们做的是**确认与纠正**，不是从头写：

1. 确认/纠正我们补的**子项名**与**结果片段归属**（我们出核对表，他们勾选）
2. 补上确实缺失的分隔符（如 `牙周检查结果牙周探诊`）
3. 确认 `level = 未提供` 的项**永远**返回"未提供"，不得给数值

**冲突时以医院为准** —— 所以数据结构保留 `result` 原文与 `source` 标记，医院意见来了能替换回去。

---

## 7. 一句话总结

**四层标签：权限层（谁能看见）→ 模块层（哪一类）→ 项层（哪一条）→ 子项层（项内分段）。**

- 前三层医院已经写好，我们只是**显式化 + 分文件**；
- 第四层医院写得时有时无，**这是我们当前要补的**，且补的是结构不是内容；
- 所有面向学生的文字**逐字来自原文**，机器校验保证这一点。
